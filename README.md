# MyHotkey

Переназначение клавиш для Windows. То же, что делает AutoHotkey, но настраивается
мышкой и стартует мгновенно.

## Почему

Чтобы настроить AutoHotkey, надо читать мануал и писать код на его языке. А на
автозагрузке он тащит рантайм и парсер скрипта, отсюда пауза после логина, когда
хоткеи ещё не работают.

Здесь это разнесено на два процесса, и в этом всё дело:

```
myhotkey-engine.exe    чистый Win32 на C, без рантайма, ~116 КБ
                       стартует при входе в систему, висит в трее
                       low-level hook + движок правил + config.json

myhotkey-ui.exe        WPF, ~44 КБ, запускается по требованию из трея
                       редактор правил; на автозагрузку не влияет вообще
```

Движок ничего не знает про UI, UI ничего не знает про клавиатуру. Общаются через
`config.json` и именованный канал. На автозагрузке — только голый нативный
бинарник, поэтому старт занимает миллисекунды.

Обе половины вместе около 160 КБ, без единой внешней зависимости. WPF взят на
.NET Framework 4.8, который уже встроен в Windows начиная с версии 1903, так что
пользователю качать нечего.

## Установка

```
winget install agufranov.MyHotkey
```

Одна команда, один запрос UAC — и всё. Движок запускается сразу, не дожидаясь
следующего входа в систему, и дальше поднимается сам. Обновление —
`winget upgrade`, удаление — `winget uninstall agufranov.MyHotkey`.

Правила по умолчанию идут **выключенными**: три примера видны в окне настроек,
включаются галочкой. Молча переназначать CapsLock на машине, куда нас только что
поставили, было бы невежливо.

Альтернатива — установщик `build\MyHotkey-Setup-1.0.0.exe`, 2,1 МБ. Обычный
мастер, запись в «Программах и компонентах», ярлык в меню «Пуск». Удаление
оттуда же.

Он один раз спросит права администратора, и вот зачем. Папка «Автозагрузка» и
ключ Run запускают программы в самом конце входа в систему — ровно та задержка,
из-за которой хоткейный инструмент первые секунды кажется спящим. Задача в
Планировщике с триггером на вход срабатывает заметно раньше, а создать её без
администратора нельзя.

Наивысшие права дают и второе: перехват клавиш в окнах с повышенными
привилегиями — диспетчере задач, консоли администратора. Обычный процесс туда не
достаёт, и AutoHotkey без прав администратора тоже.

Права нужны и при удалении: движок, запущенный такой задачей, обычным
`taskkill` не снимается.

Тихая установка для развёртывания:

```
MyHotkey-Setup-1.0.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /TASKS=startup
```

При тихом удалении правила сохраняются: вопрос об их удалении задаётся только в
интерактивном режиме, а подавленный диалог вернул бы ответ по умолчанию и стёр
бы чужую работу без спроса.

Установщик не подписан — Windows покажет предупреждение SmartScreen. Для раздачи
посторонним нужен сертификат подписи кода.

Для разработки есть `install.bat` и `uninstall.bat`: то же самое, но ставят в
`%LOCALAPPDATA%` прямо из `build\` и без мастера.

## Выпуск версии

1. Поднять `AppVersion` в [installer/myhotkey.iss](installer/myhotkey.iss) и
   `PackageVersion` в трёх файлах [installer/winget/](installer/winget/).
2. `build-all.bat` — собирает всё, включая установщик.
3. Выложить `build\MyHotkey-Setup-<версия>.exe` в релиз на GitHub.
4. Подставить в манифест ссылку и хеш:
   `certutil -hashfile build\MyHotkey-Setup-<версия>.exe SHA256`
5. Отправить PR с папкой манифестов в
   [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs), в
   `manifests/a/agufranov/MyHotkey/<версия>/`. Проще через
   [wingetcreate](https://github.com/microsoft/winget-create):
   `wingetcreate update agufranov.MyHotkey --urls <ссылка> --version <версия> --submit`

Манифест уже содержит `/TASKS=startup` в ключах тихой установки, иначе winget
поставил бы программу без автозапуска — то есть почти бесполезной.

## Сборка

Нужен компилятор C и, для окна настроек, MSBuild с reference assemblies
.NET Framework. `build.bat` понимает и MinGW, и MSVC и берёт доступный:

```
build-all.bat        собрать всё и прогнать тесты
build.bat gcc        только движок, принудительно MinGW
build.bat msvc       только движок, принудительно MSVC
test\run.bat         тесты разбора сочетаний
```

Если MSBuild не найден, соберётся один движок — он самодостаточен, правила тогда
правятся прямо в `config.json`.

## Конфигурация

`%APPDATA%\MyHotkey\config.json`, создаётся при первом запуске. Редактировать
руками не нужно, но можно: движок замечает запись и перечитывает файл сам.
Если JSON битый, старые правила продолжают работать, а в трей приходит
уведомление с текстом ошибки — молчаливого отказа не бывает.

```json
{
  "version": 1,
  "rules": [
    {
      "id": "caps-layout",
      "name": "CapsLock переключает раскладку",
      "enabled": true,
      "trigger": "CapsLock",
      "on": "release",
      "action": { "type": "combo", "keys": ["Ctrl+Shift"] }
    },
    {
      "id": "alt-s-back",
      "name": "Alt+S — назад",
      "trigger": "Alt+S",
      "action": { "type": "combo", "keys": ["Alt+Left"] }
    }
  ]
}
```

### Поля правила

| Поле | Значение |
|---|---|
| `trigger` | Сочетание: `CapsLock`, `Alt+S`, `RAlt`, `LCtrl+S`. |
| `on` | `press` (по умолчанию) или `release`. |
| `enabled` | `false` временно выключает правило, не удаляя. |
| `app` | Работать только в этом процессе, например `chrome.exe`. |
| `notApp` | Работать везде, кроме этого процесса. |
| `action` | Что сделать, см. ниже. |

### Действия

| `type` | Поля | Что делает |
|---|---|---|
| `combo` | `keys` | Отправить сочетания по порядку. |
| `text` | `text` | Напечатать строку; раскладка не важна. |
| `launch` | `path`, `args` | Запустить программу или открыть ссылку. |
| `layout` | `direction` | Сменить раскладку напрямую, `next` или `prev`. |
| `block` | — | Проглотить клавишу и ничего не делать. |

`layout` надёжнее, чем подделка `Ctrl+Shift`: он не зависит от того, какое
сочетание назначено на смену раскладки в самой Windows.

### Имена клавиш

Буквы и цифры сами собой: `A`, `7`. Дальше `F1`–`F24`, `CapsLock`, `Tab`, `Enter`,
`Esc`, `Space`, `Backspace`, `Delete`, `Insert`, `Home`, `End`, `PageUp`,
`PageDown`, `Left`, `Right`, `Up`, `Down`, `Numpad0`–`Numpad9`, медиа-клавиши.

Знаки препинания словами, чтобы `+` не путался с разделителем: `Minus`, `Equals`,
`Comma`, `Period`, `Slash`, `Semicolon`, `Quote`, `Backtick`, `LBracket`,
`RBracket`, `Backslash`.

Модификаторы: `Ctrl`, `Alt`, `Shift`, `Win` — любая сторона. `LCtrl`, `RCtrl`,
`LAlt`, `RAlt`, `LShift`, `RShift`, `LWin`, `RWin` — конкретная.

Одинокий модификатор означает саму клавишу: `RAlt` — правило на правый Alt.
Модификатор перед чем-то ещё — часть аккорда: `RAlt+S`.

## Канал управления

`\\.\pipe\myhotkey`, построчный текст, одна команда — один ответ.

| Команда | Ответ |
|---|---|
| `ping` | `pong` |
| `version` | `version 1` |
| `status` | `status enabled=1 rules=2 capture=0` |
| `reload` | `ok`, конфиг перечитывается |
| `enable 0` / `enable 1` | `ok` |
| `capture on` / `capture off` | `ok` |

Пока включён захват, движок глотает **все** клавиши и шлёт в канал строки вида
`key Alt+Tab`. На этом стоит запись сочетаний в UI: текстовое поле никогда не
увидит Alt+Tab или Win+R, потому что оболочка забирает их раньше любого
приложения, а хук движка сидит ниже оболочки. Захват снимается сам через минуту
и при обрыве соединения — клавиатура не должна остаться проглоченной, если UI
упадёт.

Доступ к каналу открыт только SID текущего пользователя: движок может работать с
повышенными правами, а UI без них, и с дескриптором по умолчанию Windows
отказала бы своему же приложению.

## Что перехватить нельзя

Ctrl+Alt+Del и Win+L обрабатываются ядром и защищённым процессом winlogon. Ни
один инструмент в пользовательском режиме их не видит — это ограничение Windows,
а не приложения.

## Известные ограничения

**Нет режима «нажатие против удержания».** Правило на одиноком модификаторе
забирает клавишу целиком, поэтому она перестаёт работать как модификатор. Из-за
этого пока нельзя сделать «CapsLock — это Ctrl при удержании и Esc при коротком
нажатии». Это отдельная задача, требующая своего разбора состояний.

**Нет последовательностей.** Аккорд — одна комбинация, цепочки вида «Ctrl+K,
затем Ctrl+D» не поддерживаются.
